---
title: "Validate a .vio file"
description: "Check a .vio file offline and print its digest before you deploy."
---

A `.vio` file is a portable definition of a whole agent — prompt, model, skills,
connectors and memory — in one YAML file. Everything the agent is made of is inside the
file, so you can deploy a `.vio` someone sent you without any other assets.

<Note>
  Needs `vio` **1.0.0** or later for every check on this page. Check with `vio --version`.
</Note>

## Validate

From the [shell](/cli/shell):

```
> /validate agent.vio
```

Or as a subcommand, which is what scripts, CI and AI agents use:

```bash
vio validate agent.vio
```

Validation is local: no sign-in and no network. A valid file prints a summary of what it
contains. An invalid one exits `1` and names each field that's wrong.

Point `vio` at a folder and it looks for the `.vio` inside it (one level deep, not
subfolders):

```bash
vio validate .
```

One match is used. Several is an error that lists them; none is a distinct
"no .vio bundle found" error.

For scripts and CI, print one JSON result:

```bash
vio validate agent.vio --json
```

## What it checks

A bundle can be valid YAML, match the schema, and still fail the first time the deployed
agent runs. `vio validate` catches those cases here, where they are one edit to fix, and
`vio deploy` runs the same checks before it sends anything.

- **The schema** — every field the `.vio` format requires.
- **Artifact digests** — see [Editing a bundle](#editing-a-bundle-fix-the-digests) below.
- **Memory files the runtime can parse.** Each memory artifact needs the frontmatter the
  runtime reads, including a `meta` block:

  ```yaml
  ---
  meta:
    id: 01M3BF1F6D28KFF919GDB2PAYJ   # must equal the memory artifact's id
    schemaVersion: "1"               # a quoted string; unquoted 1 fails
  name: release-notes-run-log
  description: what this memory holds
  tags: [run-log]                    # optional; no other keys allowed
  ---
  ```

  A missing `meta` block, an unquoted `schemaVersion`, or a `meta.id` that differs from the
  artifact's id is refused, with the reason.
- **Template variables the agent never receives.** When an agent declares inputs, every
  `{name}` in the text it runs with — its first prompt, the skills it references, and the
  memory it reads or writes — must be one of them. Otherwise validation refuses the bundle
  and names the placeholder:

  ```
  artifacts[0].content.user: {date} is not an agent input — declare it in inputs, or remove the placeholder
  ```

  Declare the input, or remove the placeholder. Literal braces such as a JSON example
  (`{"a": 1}`) are fine.

## Digest

In the shell, `/digest agent.vio`. As a subcommand:

```bash
vio digest agent.vio
```

Prints the **deployment digest** — the value a deployment records, and the one `vio show`
and the Hub compare against. `--content` prints the whole-file content digest instead, and
`--json` prints both.

## Editing a bundle: fix the digests

Each artifact inside a `.vio` — every prompt, agent, skill and memory — carries its own
digest in the manifest. **Edit a body and its recorded digest no longer matches**, and the
deploy is refused. The file is still valid YAML and still passes the schema, so this is
not something you can spot by eye.

`vio validate` checks these, and `vio digest --fix` repairs them:

```bash
vio digest agent.vio --fix
```

It prints each artifact it changed, old digest to new, and rewrites **only** those lines —
your comments, key order and formatting survive. On a file that is already correct it
changes nothing and exits `0`. If it cannot rewrite the manifest it says so and writes
nothing, rather than reporting a fix it did not make. It only runs on a bundle that is
otherwise valid, so fix a schema, memory or placeholder problem first.

So the loop for editing a bundle by hand, or with an AI coding agent, is:

```bash
# edit agent.vio
vio digest agent.vio --fix     # recompute the digests you invalidated
vio validate agent.vio         # every check above; exit 0 means deployable
vio deploy agent.vio --target viorant_cloud
```

`--json` tells the failures apart, which is what an AI agent should branch on:

| Code | Meaning |
| --- | --- |
| `bundle.invalid` | Schema, YAML, memory, placeholder or discovery problem. Fix it by editing |
| `bundle.unreadable` | The file is missing or cannot be read. Check the path, not the bundle |
| `bundle.digest_mismatch` | A body was edited. Run `vio digest --fix` |
| `bundle.fix_failed` | `--fix` could not rewrite the manifest; nothing was written |

## Deploying a `.vio` you were given

<Steps>
  <Step title="Put it in a folder">
    ```bash
    mkdir my-agent && mv agent.vio my-agent/ && cd my-agent
    ```
  </Step>
  <Step title="Validate it">
    ```bash
    vio validate .
    ```
  </Step>
  <Step title="Deploy it">
    Follow [Deploy an agent](/cli/deploy). The file never contains a provider key: either
    it runs on Viorant credits, or you provide the key.
  </Step>
</Steps>
