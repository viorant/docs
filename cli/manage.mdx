Every command on this page works both ways — in the [shell](/cli/shell) as a slash
command, and as a subcommand for scripts, CI and AI agents:

```
> /list
```

```bash
vio list
```

The rest of this page shows the subcommand form. The slash forms take the same arguments;
`--json` is subcommand-only.

Wherever a command takes an `<id>`, you can give the full deployment id, a unique prefix of
at least six characters, or the deployment's exact name.

<Note>
  Needs `vio` **1.0.0** or later for `--json` on `list`, `show` and `runs`, and for
  `vio logs --include-platform`. `vio run` and `vio logs --run` need **1.0.4** or later.
  Check with `vio --version`.
</Note>

## See what's running

```bash
vio list          # your active deployments, with state and URL
vio list --all    # include stopped, revoked and failed ones
vio show <id>     # one deployment, including its full id
```

`vio list --json` prints **every** deployment you own as a JSON array, whatever its state.
`vio show <id> --json` prints one.

## Runs

```bash
vio runs <id>              # recent runs: what it was asked and how each ended
vio runs <id> --limit 100  # up to 200
vio runs <id> --json       # as JSON, including digests
```

`vio runs` prints an 8-character id for each run. That short id works as `--run` on
[`vio logs`](#logs).

To call a deployed agent once and watch the run, use `vio run`:

```bash
vio run <deployment> --task "Summarise the last three commits"
vio run <deployment> --input '{"repo": "viorant/docs"}'
vio run <deployment> --input @input.json
```

Give it either `--task "<text>"`, for an agent with a single string input, or
`--input <json|@file>`, a JSON object inline or from a file. They cannot be combined.
`vio run` uses the run key `vio deploy` saved on this machine, so you do not pass one. A run
spends credits from your wallet. `--json` prints each run event as its own JSON line.

If the agent has connectors still awaiting authorisation, `vio run` refuses and tells you
to run [`vio connect`](/cli/connectors#vio-connect) first. If no run key is saved for the
deployment — it was deployed before this version, or from another machine — `vio run` says
so and stops. The `curl` command `vio deploy` printed still works if you kept it.

## Logs

```bash
vio logs <id>
```

Prints what **your agent** wrote — its own output — newest first, from the last day. When
there are more, the last line is the exact command for the next page.

| Option | What it does |
| --- | --- |
| `--since 2h` | Start further back: `15m`, `2h`, `1d`, or an ISO-8601 time |
| `--limit 100` | Lines per page (default 50, at most 200) |
| `--run <run id>` | Show only one run's logs. Use the 8-character id from `vio runs`, or any longer prefix of the run id |
| `--include-platform` | Also show Viorant Cloud's own platform and system lines for the service |
| `--page-token <token>` | Continue from a previous page |
| `--json` | The raw response as one JSON object, for scripts |

To read what one run did, find its id with `vio runs`, then:

```bash
vio logs <id> --run 1a2b3c4d
```

`--run` cannot be combined with `--include-platform`.

Logs can contain sensitive data. Before printing, `vio` strips terminal control sequences
and redacts common credential shapes. Read [Deployment logs](/deploy/deployment-logs)
before you share log output or hand it to an AI agent.

## Schedule

Run a deployment on its own cadence instead of triggering it yourself:

```bash
vio schedule <id> --every 1h --at :15
vio schedule <id> off   # pause; on resumes
```

Full flags, actions and plan limits: [Command reference](/cli/reference#vio-schedule) and
[Schedule an agent](/deploy/schedule-an-agent).

## Redeploy

Changed the agent? Deploy the new file onto the **same** deployment:

```bash
vio redeploy <id>
```

Run it from the folder that holds the updated `.vio`. The URL and run key stay the same,
so anything already calling the agent keeps working. A redeploy sends only the bundle —
the agent keeps the credentials it already holds.

## Stop

```bash
vio stop <id>
```

Stops the agent and revokes its credentials. **A stopped agent can't be restarted** — the
URL and run key are gone. Deploy again to get a new one.
