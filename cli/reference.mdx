## Commands

| Command | What it does | In the shell | Needs sign-in |
| --- | --- | --- | --- |
| `vio init [dir]` | Turn a folder into a Space | `/init` | — |
| `vio login` | Sign in with Google in your browser | `/login` | — |
| `vio whoami` | Show the signed-in account | `/whoami` | Yes |
| `vio status` | Plan, credits, usage and deploy quota | `/status` | Yes |
| `vio upgrade` | Show your plan and where to change it | `/upgrade` | — |
| `vio logout` | Clear this machine's credentials | `/logout` | — |
| `vio validate <path>` | Check a `.vio` file, offline | `/validate` | — |
| `vio digest <path>` | Print a `.vio` file's deployment digest; `--fix` repairs artifact digests | `/digest` | — |
| `vio deploy <path>` | Deploy a `.vio` to Viorant Cloud | `/deploy` | Yes |
| `vio connect <id> [path]` | Authorise a deployed agent's connectors | — | Yes |
| `vio list` | List your active deployments; `--all` for every one | `/list` | Yes |
| `vio show <id>` | Show one deployment | `/show` | Yes |
| `vio runs <id>` | Recent runs of a deployment | `/runs` | Yes |
| `vio logs <id>` | Recent logs of a deployment | `/logs` | Yes |
| `vio schedule <id> [action]` | Set, show, turn on or off, or clear a deployment's run schedule | `/schedule` | Yes |
| `vio redeploy <id>` | Replace a running agent in place | `/redeploy` | Yes |
| `vio stop <id>` | Stop a deployment and revoke its credentials | `/stop` | Yes |
| `vio providers` | Model providers a bundle can run on | — | — |
| `vio connectors [term]` | Browse the connector catalogue | — | — |
| `vio docs [topic]` | Print embedded documentation, offline | — | — |
| `vio update` | Install the current `vio` release | — | — |
| `vio help` | List commands; `--json` prints the machine-readable manifest | `/help` | — |

Running `vio` with no arguments opens the [interactive shell](/cli/shell). A dash in the
shell column means the command is subcommand-only.

`vio <command> --help` shows every option.

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success |
| `1` | General failure |
| `2` | Usage error — invalid arguments or unknown command |
| `3` | Authentication required — run `vio login` |
| `4` | Out of credits |

## Error codes

With `--json`, every failure is reported the same way:

- **stdout is empty**, and the **last line on stderr** is one JSON object:

  ```json
  {"error":{"code":"auth.required","message":"Not signed in. Run vio login."}}
  ```

  `code` is one of the codes below. Some commands add fields inside `error` — a failed
  `vio deploy` or `vio connect` adds the `stage` it stopped at, and `vio connect` adds what
  happened to the running `agent` — but `code` and `message` are always there.
- **`vio validate` and `vio digest` are the exceptions**: they print the error object on
  stdout, because a validation result is their output.
- The **exit code** always matches: a sign-in failure exits `3` from every command,
  including `vio deploy` and `vio connect`; an invalid argument exits `2`; out of credits
  exits `4`.

A command line `vio` cannot parse at all — a missing required argument, an unknown option —
is rejected before any command runs, as one plain-text line (`error: …`) with exit `2`.

| Code | Meaning |
| --- | --- |
| `auth.required` | The command needs a signed-in Viorant account |
| `wallet.empty` | The wallet has no credits for a metered operation |
| `bundle.invalid` | A `.vio` failed schema, YAML, memory, template-variable, connector-tool or discovery checks |
| `bundle.unreadable` | The `.vio` file is missing or cannot be read; the bundle itself was never examined |
| `bundle.digest_mismatch` | An artifact body was edited; run `vio digest --fix` |
| `bundle.fix_failed` | `digest --fix` could not rewrite the manifest; nothing was written |
| `deploy.not_available` | Deploy is unavailable for the requested target or state |
| `usage.invalid` | Arguments or flags are invalid |
| `cli.not_implemented` | The command is registered but not implemented yet |
| `space.exists` | `vio init` found an existing Space, or `--force` was refused without confirmation |
| `space.init_failed` | `vio init` could not write the Space |
| `schedule.not_found` | The deployment has no schedule |
| `schedule.interval_below_plan` | The schedule is more frequent than your plan allows |
| `schedule.invalid_spec` | The schedule's interval, time or time zone was rejected |
| `schedule.invalid_input` | The schedule's `--input` payload was rejected |
| `schedule.deployment_not_schedulable` | Only a running deployment on Viorant Cloud can be scheduled |
| `cli.upgrade_required` | Reserved — your `vio` is too old |
| `rate_limited` | Reserved — too many requests |

## Machine-readable manifest

```bash
vio help --json
```

Prints every command with its arguments and options, whether it has a shell form, whether
it needs sign-in or network, whether it creates cloud resources, moves credentials or
spends credits, and the exit and error code tables above. Scripts and AI agents should
read this instead of parsing `--help`.
